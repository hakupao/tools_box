# DataForge Studio v3 重构设计

- 日期：2026-10-29
- 对象仓库：`tools_box`（产品名 DataForge Studio），当前基线 v2.0.2
- 目标版本：v3.0.0

## 1. 为什么要做

v2 的功能本身能用，但实现过程很拧巴：

- **界面**：强制浅色主题，再用约 470 行手写 QSS、标题栏 DWM 补丁、关闭原生对话框等手段去"修"它。
  - 34 处文字颜色把亮色和暗色写成同一个值。
  - 9 个页面各写各的骨架，简单页面约 60% 是复制粘贴。
  - 几乎所有耗时操作都在 UI 线程里跑，靠 `processEvents()` 维持界面。
- **后端**：14 个服务模块有 5 种返回约定、6 种输出命名方式、多套编码规则和 5 套日期解析，没有日志。
  - 部分行为会悄悄损坏数据，例如去引号会去掉首尾空格，全角转半角会丢失 Excel 格式。

v3 的三个目的：

1. 做出一个"本来就该这么写"的干净版本，给作者自己和同事日常使用，也作为技术作品展示。
2. **作者借此学习 PySide6 / QFluentWidgets 图形界面的标准写法**。因此可读性和"标准、地道"的写法优先于少写几行代码。
3. Python 版是**过渡版**，之后会用 C# 或 Rust 再写一遍。因此每个工具的规则说明和标准样例要能脱离 Python，直接给新语言版本做对照验收。

## 2. 目标、非目标、反目标

### 目标

- 主题跟随 Windows 亮/暗模式，也可以手动切换。不写任何手工颜色补丁。
- 所有工具页共用一套响应式骨架，窗口宽度变化时排版依然好看。
- 所有耗时任务都在后台线程运行，界面不卡，可以取消，并显示进度。
- 后端与 Qt 完全解耦。返回值、进度、错误、编码、输出命名统一为一套约定，并有日志。
- 每个工具配一份规则说明和一套标准样例（固定输入加期望输出），并有自动对照测试。

### 非目标

- 不保留：仕様書工作流（DataSet 生成、数据清洗、Codelist 三种模式）和死链检测。代码、文档、依赖一并删除。
- 不做数据模糊化的 Pattern2（EDC 模式），删除现有占位页。
- 不做多语言界面，界面保持中文。
- 不做 macOS/Linux 适配。
- 不在 v3 里引入新工具。

### 反目标（出现以下情况，即使能跑也算失败）

- 又出现手写颜色、手写 QSS、按像素写死的宽度，或强制某种主题的代码。
- 任何工具在用户没有明确选择的情况下覆盖原文件。
- 编码识别失败时，把乱码当作成功输出。
- 处理过程中界面卡住，或者无法取消。
- 业务规则写在页面代码里，导致规则说明和代码对不上。

## 3. 约束

- Windows 10/11，Python 3.11。
- 技术栈沿用 PySide6 + QFluentWidgets（`PySide6-Fluent-Widgets`）+ pandas + openpyxl。EDC 继续使用 pywin32（COM）、pyautogui、keyboard、mouse、pyperclip。
- 继续用 PyInstaller onedir 和 Inno Setup 打包，`packaging/scripts/` 下的三个脚本继续可用。
- 用户本地已有的 v2 配置要能读取：数据模糊化的 `data_masking_pattern1` 配置档，EDC 的 `edc_site_adder` 点击坐标等。不能让同事升级后重新配置一遍。
- CSV 输出统一为 UTF-8 BOM（`utf-8-sig`），与 v2 一致。

## 4. 保留的 7 个工具

| 分组 | 工具 | 说明 |
|---|---|---|
| 文件处理 | 格式转换 | CSV→XLSX、XLSX→CSV、CSV 转 UTF-8 BOM、CSV 去引号 |
| 文件处理 | 工作表拆分 | 每个 sheet 输出一个 CSV（与 XLSX→CSV 共用一套逻辑，见 §7.2） |
| 文件处理 | 获取字段 | 批量读取 CSV/XLSX 表头，导出汇总 |
| 业务 | 数据模糊化 | SDTM Pattern1：扫描 → 配置 → 执行 |
| 业务 | EDC 站点添加 | 录制点击坐标 → 从 Excel 逐行回放 |
| 小工具 | 日期转换 | 文本中的 `YYYY/MM[/DD]` 转为 ISO 8601 |
| 小工具 | 全角转半角 | Excel 文件内的全角英数和符号转为半角 |

## 5. 界面设计（已和作者确认）

### 5.1 主题

- 默认 `Theme.AUTO`，跟随系统。设置页提供"跟随系统 / 浅色 / 深色"三个选项，选择结果持久化保存。
- 开启 FluentWindow 的 Mica 效果。
- 恢复原生文件对话框。删除 `AA_DontUseNativeDialogs`、`DontUseNativeDialog`、标题栏 DWM 补丁、`_LIGHT_DIALOG_STYLE` 和所有滚动条 QSS。
- 全部使用 Fluent 组件，例如 `ScrollArea`/`SmoothScrollArea`、`CardWidget`/`SimpleCardWidget`、`PlainTextEdit`、`TableWidget`、`ListWidget`、`MessageBoxBase`、`InfoBar`，不混用会脱离主题的原生 Qt 控件。
- 确实需要语义色（成功、警告、错误）时，统一用 `setTextColor(light, dark)` 成对的颜色，或者 QFluentWidgets 自带的主题色工具，并集中定义在一个模块里。
- 唯一例外是 EDC 录制浮层：它是自绘的半透明悬浮层，允许使用固定配色。
- `docs/UI界面规范.md` 要整体重写。现在这份文档把强制浅色、hex 调色板、`processEvents` 都写成了规范，不能留着误导后来的人。

### 5.2 外壳与导航

- FluentWindow。侧边栏依次是"主页"，然后按"文件处理 / 业务 / 小工具"三组排列工具，底部放"设置"。
- **工具统一登记在一处**：每个工具一条记录，包含 id、名称、简介、分组、FluentIcon、页面类。主页卡片、侧边栏和页面标题都从这份登记生成，名称只写一次。
- 页面类不依赖 `main_window`，也不再提供"返回主页"按钮，因为侧边栏已经承担了这个作用。
- 页面延迟加载：第一次进入某个工具时才创建它的页面。

### 5.3 主页（作者选了方案 B）

- 上半部分是"最近使用"。每条记录显示工具名、输入文件摘要和时间，点击后跳到对应工具，并恢复当时的输入文件和参数。
  - 只保留最近 10 条。（构建者决定）
  - 如果原输入文件已经不存在，只恢复参数，并用 InfoBar 提示，不报错。（构建者决定）
- 下半部分是全部工具的紧凑卡片格，整张卡片可点击，宽度变化时自动换行。可以用 `FlowLayout` 或等效做法。

### 5.4 工具页骨架（作者确认：按宽度自动切换）

同一个页面在三种宽度下分别这样排：

| 窗口宽度 | 排法 |
|---|---|
| 宽（≥ 1100 px） | 左侧是"输入 + 参数"卡片，右侧是结果区。操作条固定在底部，包含进度条、计数、取消按钮和主按钮。 |
| 中（750–1100 px） | 侧边栏收成图标，内容改为上下排列：输入 → 参数 → 结果。操作条仍固定在底部。 |
| 窄（< 750 px） | 单列。参数表单改为标签在上、输入在下。结果区折叠成一行摘要，点开后展开。 |

规则：

- 窗口最小宽度约 640 px。
- 不写死像素宽度。参数表单用同一个组件，按宽度在"标签 | 输入"两列和单列之间自动切换。
- 结果区统一分为三个标签页：**结果 / 警告 / 日志**。
- 运行期间锁定输入区和参数区，切换侧边栏不受限制，任务在后台继续执行。（构建者决定）
- 全局同一时间只运行一个任务。任务运行时，其他工具页的主按钮不可用，并提示"<工具名> 正在运行"。原因是 EDC 会实际控制鼠标和键盘，不能和其他任务同时进行。（构建者决定）
- 结果提示一律用 InfoBar。模态对话框只用于需要用户确认的场景，例如勾选了覆盖原文件时的二次确认。
- 日期转换这类"输入文本、立刻出结果"的小工具，使用骨架的简化版：左右两个文本框加一个按钮，不需要操作条。
- 数据模糊化和 EDC 步骤较多，在同一套骨架里放更多卡片，可以用分步卡片或 `SegmentedWidget` 组织。

草图存放在 `.superpowers/brainstorm/` 下：`page-layout-v2.html` 是工具页骨架，`home.html` 是主页。这个目录需要加入 `.gitignore`。

### 5.5 设置页

- 主题：跟随系统 / 浅色 / 深色。
- 打开日志文件夹、打开配置文件夹。
- 清空"最近使用"。
- 显示版本信息。

## 6. 后端设计

### 6.1 统一约定

- **纯函数风格**：每个工具的核心入口形如 `run(inputs, options, progress, cancel) -> Result`。
  - 不导入 Qt，不读取应用配置，不使用 `print`，不在内部写死界面默认值。
  - 默认值放在各工具的 options dataclass 里。
- **Result**：统一的结构化结果，包含输出文件列表、警告列表、错误列表和统计数字。
  - 非法输入抛出明确的 `ValueError` 子类（统一的异常基类）。
  - 单个文件失败时，记入 Result 的错误列表，然后继续处理下一个文件。
- **进度与取消**：进度回调为 `(current, total, label)`；取消用一个令牌对象，工具在每个文件或每批行之间检查它。
- **日志**：使用标准 `logging`，写入用户目录下的滚动日志文件，界面的"日志"标签页同步显示。

### 6.2 统一 IO 规则

- **读 CSV**：一律 `dtype=str`、`na_filter=False`。
  - 编码识别（作者确认：日文和中文数据都有）：
    - 先试 UTF-8(BOM) → UTF-8，成功就采用。
    - 都失败时，分别用 cp932 和 GBK 试解码：
      - 只有一种成功：采用这一种，并在警告里注明。
      - 两种都成功：视为**有歧义**，这个文件不处理，标记为"需要选择编码"。界面显示两种解码各自的前几行预览，用户为该文件选定编码后再运行。
      - 都失败：报错。
    - **不用 latin1 兜底。**
  - 页面上可以手动指定编码，此时跳过自动识别。
  - 自动识别的结果写进日志。
  - 这一套识别逻辑放在公共 IO 模块里，所有读 CSV 的工具共用。
- **读 Excel**：一律按文本读取（`dtype=str`、`na_filter=False`），或者用 openpyxl 读单元格，跟随单元格自身的格式。具体见各工具的规则。
- **写 CSV**：`utf-8-sig`。
- **输出位置和命名**（作者确认：绝不覆盖原文件）：
  - 默认输出到原文件所在目录，生成新文件名。也可以在参数里选择另一个输出目录。
  - 目标文件已存在时，自动加 `_1`、`_2`……，不静默覆盖。
  - 参数里有一个显式的"覆盖原文件"选项，默认关闭；勾选后运行前会二次确认。
  - 输出文件名规则写在每个工具的规则说明里，由一个公共的输出路径模块统一实现。
- **批量输入**：选择文件夹时跳过 `~$` 开头的 Office 临时锁文件。
- **日期**：所有日期解析和标准化都集中在一个模块里，各工具只调用它，不再各写一套。

### 6.3 配置

- 继续使用一个 JSON 配置文件，按 section 分区存储。
- 新增 `app`（主题等）和 `recent`（最近使用）两个 section。
- 每个 section 用一套统一的读取 / 合并默认值 / 迁移 / 保存逻辑。
- 保存时先写临时文件，再原子替换。
- 配置文件损坏时，**先把它备份成 `.bak` 再用默认值**。v2 的做法是当成空配置，下一次保存就会把其他 section 全部冲掉，要避免这个问题。
- 迁移：继续兼容读取 v2 的配置路径和 section 名（`data_masking_pattern1`、`edc_site_adder`），包括 v2 已经支持的旧版配置位置。v2 里两份重复的迁移代码合并成一份。

## 7. 各工具规则

下面只列 v3 的规则，以及与 v2 不同的地方（标为【变更】）。没有标变更的行为，以 v2 当前实现为准，构建时要把它写进该工具的规则说明里。

### 7.1 格式转换

- **CSV → XLSX**：单个 sheet，名称为 `Sheet1`，所有单元格设为文本格式（`@`）。输出 `<stem>.xlsx`。
  - 【变更】读取时使用统一的编码识别；输出目录不存在时自动创建。
- **XLSX → CSV**：【变更】改为调用工作表拆分的同一套逻辑（见 §7.2），提供"只取第一个 sheet（默认）/ 全部 sheet"选项。
  - 日期按单元格格式输出，不再写成 `2020-01-01 00:00:00`。
  - 只取第一个 sheet 时，输出 `<stem>.csv`。
- **CSV 转 UTF-8 BOM**：自动识别编码后另存为 `utf-8-sig`。【变更】默认输出新文件，不再覆盖原文件；识别失败就报错。
- **CSV 去引号**：【变更】按标准 CSV 规则读取，然后不加引号写出。
  - 字段内容原样保留，包括首尾空格和内容里的引号。
  - 如果某个字段含有分隔符或换行，去掉引号后会破坏 CSV 结构。这种情况要列入警告，由构建者决定该字段保留引号还是跳过整个文件，并写进规则说明。
  - 分隔符自动识别（沿用 v2 的嗅探方式）。
  - 默认输出新文件。

### 7.2 工作表拆分（与 XLSX→CSV 共用）

- 用 openpyxl 只读模式打开，每个 sheet 输出一个 CSV。
- 日期按单元格的 `number_format` 输出。
- sheet 名称做 Windows 文件名安全处理，重名时加 `_n`。
- 去掉末尾的空行和空列。
- 以上都与 v2 一致。输出目录和命名规则遵循 §6.2。
- 输出文件名（构建者决定）：
  - 工作表拆分，以及 XLSX→CSV 的"全部 sheet"模式：输出 `<stem>_<sheet>.csv`。v2 只用 `<sheet>.csv`，批量处理时不同工作簿的 `Sheet1` 会互相冲突。
  - XLSX→CSV 的"只取第一个 sheet"模式：仍输出 `<stem>.csv`。

### 7.3 获取字段

- 读取指定行号作为表头（从 1 开始计数），支持 csv/xlsx/xlsm，可选是否包含子文件夹。
- 汇总文件为 `file_fields_summary.csv`。
- 【变更】汇总文件不能被下一次运行当作输入文件读进去，构建者可以选择排除它，或者默认输出到别的位置。
- 跳过 `~$` 临时文件。

### 7.4 数据模糊化（SDTM Pattern1）

沿用 v2 的规则：

- **扫描**
  - 只接受 CSV。必须有且只有一个 `DM.csv`（文件名不区分大小写）。
  - 每个文件都必须包含 USUBJID 列（列名不区分大小写）。
  - 统计每个文件的非空字段和空字段。
  - 日期列识别：取前 `sample_size`（200）个非空值，其中能解析为日期的比例要 ≥ `ratio`（0.8）；如果非空值少于 `min_non_empty`（20）个，则要求比例为 100%。
  - 受试者 = DM 中的 USUBJID，去重后按字符串排序。
- **执行**
  - 只取前 `subject_limit`（100）个受试者，删除所有文件中其他受试者的行。
  - 新 ID 有两种生成方式：
    - 顺序编号：`TEST` + 从 `start` 开始、补零到 4 位的序号；
    - 规则链：去前缀 4 位 → 去后缀 → 加前缀 `SKLT` → 加后缀。
  - 生成的新 ID 有重复时报错。
  - 所有行的 STUDYID 设为 `[UAT]CIRCULATE`。
  - 日期列整体偏移 `date_shift_years`（−2）年；2 月 29 日落到非闰年时取当月最后一天。
  - 部分日期 `YYYY` / `YYYY-MM` 补成当月 01 日，并计入"自动补全"计数。
  - 无法解析的值保持原样，并计数。
  - 仅针对 DM，且仅当扫描时该列有值：
    - 医生字段（INVNAM）改为 `テスト医師`，SITEID 改为 `テスト施設`，只改非空单元格，两项各自可以开关。
    - AGE 加上 `age_shift`，最小为 0，整数仍保持整数。
  - 输出：
    - 一个 `masked_output_YYYYmmdd_HHMMSS` 文件夹，放在 DM.csv 同级目录，文件名与输入相同；
    - 另附 `usubjid_mapping.csv`（OLD/NEW）和 `pattern1_scan_report.json`。
  - 如果文件列表或 3 个识别参数（sample_size、ratio、min_non_empty）有变化，界面要求重新扫描。
- 【变更】**SUBJID**：作者决定，勾选"处理 SUBJID"时，输出中 SUBJID 列**直接清空**。v2 用 USUBJID 的映射去替换 SUBJID，实际上基本替换不上。
  - 默认值仍为勾选。读取 v2 配置时沿用其中保存的值。
  - 执行前的摘要里要明确写出"SUBJID 列将被清空"。
- 【变更】**带时间的值**：日期偏移后保留原来的时间部分，例如 `2020-01-02T10:30` 变成 `2018-01-02T10:30`。
- 【变更】**有歧义的日期**：`xx/xx/yyyy` 只在没有歧义时自动判断，例如某一位大于 12。如果一列里存在无法判定的值，就在扫描结果里对该列给出警告，并让用户为这一列选择"日/月"或"月/日"顺序。用户没选之前不能执行。
- 【变更】删除从未生效的配置项：`subject_sort`、`date_output_format`、`partial_date_policy`。读取 v2 配置时忽略这几项。
- 【变更】页面不再重复写一份默认值，统一来自 Profile 的 dataclass；扫描签名的计算也移到服务里。
- 不在本次范围内：RELREC、SUPP 的 IDVARVAL 等其他列里出现的 USUBJID 不重新映射；没有 USUBJID 的试验设计域（TS、TA 等）仍然不支持。规则说明里要明确写出这两点限制。

### 7.5 EDC 站点添加

沿用 v2 的规则：

- 通过 COM 连接 Excel，从当前选中的单元格开始逐行向下处理，遇到空单元格或达到 `max_loops`（100）时停止。
- 每一行的处理步骤：
  - 把单元格的 `.Text` 复制到剪贴板；
  - 激活目标浏览器窗口；
  - 按顺序点击 7 个位置：新建 → 查找 → 搜索框（Ctrl+V）→ 搜索 → 选择 → ok → 确认，每步之后等待 `step_delay`（0.3s）；
  - 切回 Excel，选中下一行。
- 按 ESC 停止。
- **录制**：一个置顶浮层。用户点"开始"后，按步骤顺序记录鼠标左键按下的位置；忽略顶部 70 px 内的点击；按 ESC 取消；可以单独重录某一步。
- **回放测试**：每隔 600 ms 依次闪一个标记，每个标记显示 1.5 s。

变更：

- 【变更】**目标窗口**：录制时记住用户点击的那个浏览器窗口（窗口句柄，加上标题和进程名作为备用匹配），运行时操作这个窗口。v2 是找"第一个标题含 Chrome 的窗口"。
  - 旧配置里没有窗口信息，首次运行时提示用户录制，或者选择目标窗口。
- 【变更】**失败即停**：某一行出错就立即停下，删除自动整套重试，避免重复添加站点。
  - 配置里的 `retry_count` 读取时忽略。
  - 能检测到的"失败"只有异常类错误：目标窗口找不到或无法激活、Excel COM 出错、剪贴板出错、用户按了 ESC。程序无法判断一次点击是否真正生效，规则说明里要写明这一限制。
  - 停下后弹窗说明第几行、第几步出错以及原因，提供三个选择（作者确认）：
    - **重做本行**：从第 1 步开始。弹窗里提醒用户先确认 EDC 中这一行是否已经添加过。
    - **跳到下一行**
    - **结束**
  - 运行结束后的汇总列出：成功的行、被跳过的行、出错的行。
- 【变更】**线程安全**：
  - ESC 热键只在任务运行期间注册，结束后只注销自己注册的那个热键，不再调用全局的 `unhook_all`。
  - 鼠标钩子和键盘钩子线程里的回调只发信号，不直接操作界面控件。
- 【变更】点击执行逻辑可以注入，包括点击、剪贴板、Excel、窗口激活这几部分，以便在不操作真实屏幕的情况下测试循环逻辑。
- 【变更】修正 `WNDENUMPROC` 的类型声明。（v2 的窗口枚举方式可能整体被替换。）

### 7.6 日期转换

- 对每一行文本，把 `YYYY/MM[/DD]` 转成 ISO 8601。
- 月份无效时截断到年，日期无效时截断到年月。
- 无法解析的值保持原样。
- 【变更】日期要做真实日历校验，例如 2 月 31 日视为无效，按上一条规则截断到年月。
- 使用 §6.2 中统一的日期模块。

### 7.7 全角转半角

- 【变更】用 openpyxl 逐个修改文本单元格，保留格式、公式和合并单元格。
- 【变更】表头也一起转换。
- 转换范围：全角英文、数字、ASCII 符号转为半角，全角空格转为半角空格。**不改动日文假名和汉字**，所以不能直接用 NFKC。
- 公式单元格不改动。
- 默认输出新文件。

## 8. 规则说明与标准样例

- 每个工具一份规则说明，放在 `docs/tools/<tool>.md`（具体路径由构建者决定）。内容包括：
  - 输入要求、参数及默认值；
  - 处理步骤、输出位置和命名；
  - 编码规则、边界情况、已知限制。

- 每个工具配一组标准样例，每个样例包含：输入文件、参数（JSON）、期望输出文件。
  - 有一个对照测试，用 Python 版逐个运行样例，并与期望输出逐字节或逐单元格比较。
  - 样例要覆盖本文档中所有【变更】项和主要边界情况。
  - 数据模糊化的样例数据必须是虚构的。
- 规则未变的部分，可以先用 v2 跑出结果作为期望输出；有变更的部分，期望输出按本文档人工确认。
- 现有的 `tests/test_data_masking_service.py` 和 `tests/test_unified_config_services.py` 按新结构迁移；规则有变化的地方（例如 SUBJID），测试要相应更新。

## 9. 代码结构（构建者决定）

方向如下：

- 重组为一个独立的包，例如 `src/dataforge/`。
- 按"核心约定 / IO / 配置 / 各工具后端 / 界面"分层：
  - 界面层内再分为外壳、公共组件、后台任务运行器、各工具页面；

- 所有页面共用同一个任务运行器。
