# 应用图标重做 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用一个手写的透明背景 SVG（2×2 四格工具）生成新的多尺寸 `assets/icons/favicon.ico`，替换现在带白底的插画图标。

**Architecture:** `assets/icons/app_icon.svg` 是源文件；`scripts/build_icon.py` 用 PySide6 的 `QSvgRenderer` 把它渲染成六个尺寸，再由脚本自己写出 ico 文件头，每个尺寸存成一条 PNG 记录。引用 `favicon.ico` 的地方都不改。

**Tech Stack:** Python 3、PySide6（QtSvg、QtGui），unittest 风格测试，由 pytest 运行。

**Spec:** `docs/superpowers/specs/2026-11-16-app-icon-design.md`

## Global Constraints

- 尺寸固定为 16、32、48、64、128、256，全部放进同一个 `assets/icons/favicon.ico`。
- 背景透明，不能有方形白底。
- 文件名和引用位置都不改：`src/dataforge/ui/resources.py`、`packaging/pyinstaller/tools_box_onedir.spec`、`packaging/installer/tools_box.iss` 一行都不动。
- 不新增运行或开发依赖（不装 Pillow）。
- 脚本放在 `scripts/` 下，不放进 `src/dataforge/`：它是开发工具，不进安装包。
- 测试遵守 AGENTS.md：放在 `tests/dataforge/test_<主题>.py`，unittest 风格，Qt 用 `tests/dataforge/qt_helpers.py` 的 `qapp()`，IO 用临时目录。

## Review Focus

1. Qt 读回新 ico 时必须能拿到全部六个尺寸。窗口图标靠 Qt 读取，如果读不出来，标题栏就没有图标。→ Task 1 的 `test_qt_reads_back_all_sizes`。
2. 256 尺寸在 ico 目录里的宽高字节要写 0。写成 256 会溢出成 0 以外的值，Windows 资源管理器会显示错乱。→ Task 1 的 `test_header_layout`。
3. 每个尺寸的四个角都必须透明，不能只检查 256。→ Task 2 的 `test_favicon_corners_transparent`。
4. 提交的 `favicon.ico` 必须和当前的 SVG 一致，避免改了 SVG 却忘记重新生成。→ Task 2 的 `test_favicon_matches_svg`。
5. 打包后的程序还要能找到图标。`app_icon_path()` 的现有测试保留不动，最后跑全部测试即可覆盖。

### Task 1: ico 生成脚本

**Files:**
- Create: `scripts/build_icon.py`
- Test: `tests/dataforge/test_build_icon.py`

**Interfaces:**
- Produces（Task 2 使用）：
  - `SIZES: tuple[int, ...] = (16, 32, 48, 64, 128, 256)`
  - `render_svg(svg_path: Path, size: int) -> QImage`：返回 `Format_ARGB32_Premultiplied`、`size×size`、先填透明再渲染的图像。
  - `encode_png(image: QImage) -> bytes`
  - `build_ico(pngs: list[tuple[int, bytes]]) -> bytes`：参数是按尺寸排好的 `(边长, PNG 字节)` 列表。
  - `main(argv: list[str] | None = None) -> int`：参数为 `--svg`（默认 `assets/icons/app_icon.svg`）和 `--out`（默认 `assets/icons/favicon.ico`），都相对仓库根目录解析。
- 测试导入脚本的方式：`importlib.util.spec_from_file_location("build_icon", ROOT / "scripts" / "build_icon.py")`，因为 `scripts/` 不是包。

- [ ] **Step 1: 写失败的测试**

测试用的 SVG 直接写在测试文件里，是一个四周留透明边的红色方块：

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 256 256"><rect x="32" y="32" width="192" height="192" fill="#ff0000"/></svg>
```

- `test_render_transparent_corners`：对每个 `SIZES` 调用 `render_svg`，断言 `image.size()` 等于 `(size, size)`；`pixelColor(0, 0).alpha() == 0`；中心像素 alpha 为 255，且红色分量大于 200。
- `test_header_layout`：用两个尺寸 `[(16, b"A"*10), (256, b"B"*20)]` 调用 `build_ico`，然后断言：
  - 前 6 字节解包（`<HHH`）为 `(0, 1, 2)`；
  - 第一条目录项（`<BBBBHHII`，偏移 6）宽高为 `(16, 16)`、色深为 32、数据长度为 10、数据偏移为 `6 + 16*2 = 38`；
  - 第二条目录项宽高为 `(0, 0)`、数据长度为 20、数据偏移为 48；
  - `data[38:48] == b"A"*10`。
- `test_qt_reads_back_all_sizes`：在临时目录里跑 `main(["--svg", 测试SVG, "--out", tmp/"x.ico"])`，返回值为 0；`QIcon(str(out)).availableSizes()` 的宽度集合等于 `set(SIZES)`。

- [ ] **Step 2: 运行测试，确认失败**

Run: `.venv/Scripts/python.exe -m pytest tests/dataforge/test_build_icon.py -q`
Expected: FAIL（`scripts/build_icon.py` 不存在）

- [ ] **Step 3: 实现 `scripts/build_icon.py`**

- `render_svg`：先 `fill(Qt.transparent)`，再用 `QPainter` 开启抗锯齿，调用 `QSvgRenderer.render(painter, QRectF(0, 0, size, size))`。
- `encode_png`：用 `QBuffer` 和 `image.save(buf, "PNG")`。
- `build_ico`：
  - 文件头为 `struct.pack("<HHH", 0, 1, n)`；
  - 每条目录项为 `struct.pack("<BBBBHHII", w % 256, h % 256, 0, 0, 1, 32, len(png), offset)`；
  - 第一条数据的偏移为 `6 + 16*n`，后面每条依次累加。
- `main`：
  - 脚本里用 `QGuiApplication.instance() or QGuiApplication([])`；
  - 输出用同目录临时文件再 `os.replace`，和项目的原子写入约定一致；
  - 结束时用 `logging` 输出生成的路径和尺寸，不用 `print`。
- 文件开头写模块文档字符串，说明用法：`.venv\Scripts\python scripts\build_icon.py`。

- [ ] **Step 4: 运行测试，确认通过**

Run: `.venv/Scripts/python.exe -m pytest tests/dataforge/test_build_icon.py -q`
Expected: 3 passed

- [ ] **Step 5: 提交**

```bash
git add scripts/build_icon.py tests/dataforge/test_build_icon.py
git commit -m "feat(icon): add SVG to multi-size ICO build script"
```

### Task 2: 四格图标 SVG 和新 favicon.ico

**Files:**
- Create: `assets/icons/app_icon.svg`
- Modify (regenerate): `assets/icons/favicon.ico`
- Test: `tests/dataforge/test_build_icon.py`（追加测试）

**Interfaces:**
- Consumes：Task 1 的 `SIZES`、`render_svg`、`main`。

- [ ] **Step 1: 写失败的测试**

- `test_favicon_corners_transparent`：
  - `QIcon(ROOT/"assets/icons/favicon.ico")` 的可用尺寸集合等于 `set(SIZES)`；
  - 对每个尺寸取 `pixmap(size).toImage()`，四个角像素的 alpha 都为 0。
- `test_favicon_matches_svg`：对每个尺寸，用 `render_svg(app_icon.svg, size)` 渲染一张图，再从提交的 `favicon.ico` 取出同尺寸的图，两张都转成 `Format_ARGB32` 后逐像素比较，每个通道的差值不超过 8。不比较字节：PNG 编码和抗锯齿结果会随 Qt 版本略有差异，按字节比较容易误报。

- [ ] **Step 2: 运行测试，确认失败**

Run: `.venv/Scripts/python.exe -m pytest tests/dataforge/test_build_icon.py -q`
Expected: FAIL（`app_icon.svg` 不存在，旧 favicon 的角也不透明）

- [ ] **Step 3: 画 `assets/icons/app_icon.svg`**

以 `.superpowers/brainstorm/*/content/icon-directions.html` 里 `#iconC` 的草图为起点：
- 画布：viewBox `0 0 256 256`；
- 四个方块：位置 `(20,20)`、`(134,20)`、`(20,134)`、`(134,134)`，边长 102，圆角 `rx=24`；
- 四格的颜色和图案（白色 `#fff`）：
  - 左上：蓝 `#2B7DE9`，转换，双向箭头；
  - 右上：青 `#18A3A0`，拆分，左右两栏；
  - 左下：紫 `#6C5CE7`，提取，在放大镜和三行文字里选 32 像素下更清楚的那个；
  - 右下：橙 `#F5A524`，模糊化，划掉的眼睛。
- 线条至少 10 个单位粗（256 画布上），保证 32 像素下仍有约 1 像素宽。
- 不加背景矩形。

- [ ] **Step 4: 生成 ico 并检查小尺寸**

Run: `.venv\Scripts\python scripts\build_icon.py`
Expected: 日志里列出六个尺寸，`assets/icons/favicon.ico` 已更新。

把 16、32、48 各放大 8 倍（`scaled(..., Qt.FastTransformation)`），分别贴在浅灰和深灰底上，存成一张 PNG 放到 scratchpad，给用户看。用户认可后再继续；如果 16 或 32 糊了，回到 Step 3 调整线条粗细或简化图案。

- [ ] **Step 5: 运行全部测试**

Run: `.venv/Scripts/python.exe -m pytest tests -q`
Expected: 全部通过（含 `test_selfcheck.py::test_app_icon_path_dev`）

- [ ] **Step 6: 提交**

```bash
git add assets/icons/app_icon.svg assets/icons/favicon.ico tests/dataforge/test_build_icon.py
git commit -m "feat(icon): replace app icon with transparent four-tile design"
```
